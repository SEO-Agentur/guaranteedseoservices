Design System

Visual specification and regression reference for the shared gss-* design system. The theme owns presentation (tokens, components, layouts and templates in gss.css); Gutenberg owns content (blocks composed from these classes). If something here looks wrong after a theme update, fix gss.css, never a page.

Workflow

How to build a new page

The short version: compose from existing components, never style in content.

  1. Start from patterns: insert a pattern from the “Guaranteed SEO design system” category, or copy a section from this page or a migrated page.
  2. Compose: stack gss-section › gss-wrap › gss-head + components; put the single H1 in the first gss-hero; give sections an anchor for in-page links.
  3. No CSS in content: no style blocks, no style attributes except data values (--w, --h, --c, --x, --y), no page-specific classes; use core/html only for icons, forms, SVG and dense markup.
  4. Check: the editor shows no invalid blocks and every gss-* class exists in gss.css.
  5. Extend the theme only: add or change a generic component in theme/src/gss.css, rebuild, document it in docs/components.md and add a specimen to this page.
